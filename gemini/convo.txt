The Sample-Less .mod Specification

Because we are targeting a standard 31-instrument ProTracker format (the M.K. format), the file structure has strict byte lengths. Even if you have zero samples, you must write empty headers for all 31 instrument slots.

    Song Title: 20 bytes (Padded with null characters).

    Sample Headers (x31): 30 bytes each (Total: 930 bytes).

        Name (22 bytes)

        Length (2 bytes) -> 0x0000

        Finetune (1 byte) -> 0x00

        Volume (1 byte) -> 0x00

        Repeat Start (2 bytes) -> 0x0000

        Repeat Length (2 bytes) -> 0x0001 (Standard for empty/non-looping)

    Order Table: 130 bytes.

        Song Length (1 byte) -> Number of patterns in the sequence (1-128).

        Restart Byte (1 byte) -> Usually 0x7F, largely ignored today.

        Sequence Array (128 bytes) -> Indices of patterns to play.

    Magic Bytes: 4 bytes -> M.K. (Declares 4 channels, 31 instruments).

    Pattern Data: 1024 bytes per pattern.

        64 Rows * 4 Channels * 4 Bytes per cell.

You haven't missed anything in the code—your intuition is completely right that there are no dedicated fields for global Speed or BPM in the ModProject struct or anywhere in the .mod header.

That is because the ProTracker format does not have a header field for initial Speed or BPM. When a tracker (like MilkyTracker or OpenMPT) opens a standard .mod file, it initializes the song to a hardcoded default: Speed 6 (6 ticks per row) and BPM 125.

To change the Speed or BPM, you must explicitly inject an Fxx effect command into the very first row of your first pattern.
How the Fxx Command Works

ProTracker uses a dual-purpose effect command (0xF) to handle both Speed and BPM, using the parameter value xx to determine which one you are setting:

    Set Speed (Ticks per Row): If xx is less than 0x20 (32 in decimal), the tracker interprets it as a Speed setting.

        Example: F06 sets the speed to 6 ticks per row.

    Set BPM: If xx is equal to or greater than 0x20 (32 in decimal), the tracker interprets it as a BPM setting.

        Example: 125 BPM in hex is 7D. Therefore, F7D sets the song tempo to 125 BPM.

Because the code we wrote handles 3-character hex strings in the Effect field, the ptgen module already fully supports setting the Speed and BPM out of the box—you just apply it directly to a pattern cell.

How to Set Initial Speed and BPM in Your JSON

To establish your song's initial tempo, you format the first row of your first pattern to trigger the Fxx commands. Since you have 4 channels available per row, you can set the Speed on Channel 1 and the BPM on Channel 2 simultaneously.
